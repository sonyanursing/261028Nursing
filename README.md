# 간호학 연구실 웹사이트

교수님의 연구·수업 자료를 게시하고, 승인된 대학원생이 자료마다 댓글로 토론하며, 질문 게시판에서 묻고 답하는 웹사이트입니다.

- **사용 기술**: React + Vite(화면), Firebase(Google 로그인·데이터베이스, 무료 Spark 요금제), Netlify(배포)
- **Firebase 연동 전에도** 사이트는 정상적으로 배포됩니다. 이때 홈 화면은 그대로 보이고, 자료·로그인·토론 화면에는
  "Firebase 연동 후 사용할 수 있습니다" 안내가 나옵니다. 연동(환경변수 입력) 후에는 **코드 수정 없이** 모든 기능이 켜집니다.

## 1. 내 컴퓨터에서 실행하기 (선택)

사이트를 고치기 전에 내 컴퓨터에서 미리 보고 싶을 때만 필요합니다. 건너뛰고 2번으로 가도 됩니다.

1. **Node.js 설치**: <https://nodejs.org> 접속 → **LTS**(22 이상) 버전 내려받기 → 설치 프로그램을 끝까지 [다음] 클릭.
2. 이 저장소의 코드를 내려받습니다. GitHub 저장소 화면에서 초록색 **<> Code** 버튼 → **Download ZIP** → 압축 풀기.
3. 터미널을 엽니다.
   - Windows: 압축 푼 폴더를 연 뒤, 주소창에 `cmd` 입력 후 Enter
   - Mac: 응용 프로그램 → 유틸리티 → 터미널, 그리고 `cd ` (띄어쓰기 포함) 입력 후 폴더를 터미널 창에 끌어다 놓고 Enter
4. 아래 명령을 한 줄씩 입력합니다.

   ```bash
   npm install
   ```

   ```bash
   npm run dev
   ```

5. 화면에 나온 주소(보통 `http://localhost:5173`)를 브라우저에서 엽니다. 끌 때는 터미널에서 `Ctrl + C`.
6. (선택) 내 컴퓨터에서도 로그인까지 시험하려면 `.env.example` 파일을 복사해 이름을 `.env`로 바꾸고 4번에서 얻은
   Firebase 설정값을 채운 뒤 `npm run dev`를 다시 실행합니다. **`.env` 파일은 GitHub에 올리지 마세요**
   (`.gitignore`에 등록되어 있어 자동으로 제외됩니다).

## 2. GitHub에 올리기

이 코드는 이미 GitHub 저장소 `sonyanursing/261028Nursing`에 올라가 있습니다.
Netlify가 알아보기 쉽도록 기본 브랜치 이름을 `main`으로 바꾸는 것만 하면 됩니다.

1. <https://github.com/sonyanursing/261028Nursing> 접속 (로그인 필요).
2. 위쪽 탭에서 **Settings** 클릭 → 왼쪽 메뉴 **General**(기본 선택됨).
3. **Default branch** 항목에서 현재 브랜치 이름 옆의 연필(✏️) 아이콘 클릭 →
   `main` 입력 → **Rename branch** 클릭.
   - 이미 `main` 브랜치가 따로 있다면: 저장소 첫 화면의 **Compare & pull request** 버튼(또는 **Pull requests** 탭 →
     **New pull request**)으로 작업 브랜치를 `main`에 합친 뒤 **Merge pull request** → **Confirm merge** 를 누르세요.

> **새 저장소에 처음부터 올려야 한다면**: GitHub 오른쪽 위 **+** → **New repository** → 이름 입력 →
> **Private** 선택 → **Create repository** → 화면의 **uploading an existing file** 링크 클릭 →
> 압축 푼 폴더 안의 내용을 끌어다 놓기(`node_modules`, `dist`, `.env` 폴더/파일은 빼고) → **Commit changes**.

## 3. Netlify 배포하기

1. <https://app.netlify.com> 접속 → **Sign up / Log in** → **GitHub로 로그인**.
2. **Add new project**(또는 **Add new site**) → **Import an existing project** 클릭.
3. **GitHub** 클릭 → 권한 요청 창에서 **Authorize Netlify** → 저장소 목록에서 `261028Nursing` 선택.
   - 목록에 없으면 **Configure the Netlify app on GitHub** → 해당 저장소 체크 → **Save**.
4. 빌드 설정 화면에서 아래 값이 자동으로 채워져 있는지 **확인만** 합니다(`netlify.toml`이 알려 줍니다).
   - Branch to deploy: `main`
   - Build command: `npm run build`
   - Publish directory: `dist`
5. 환경변수는 **아직 입력하지 않아도 됩니다**. **Deploy**(Deploy 261028Nursing) 클릭.
6. 1~2분 뒤 **Published** 가 표시되면 `https://○○○.netlify.app` 주소를 눌러 홈 화면이 보이는지 확인합니다.
7. (선택) 주소 바꾸기: **Project configuration**(Site configuration) → **Change project name** → 원하는 이름 입력 → **Save**.
   → 주소가 `https://원하는이름.netlify.app` 이 됩니다. **이 주소를 메모해 두세요** (4-3단계에서 사용).

이 단계까지 마치면 홈 화면은 정상, 자료·로그인 메뉴에는 "Firebase 연동 후 사용할 수 있습니다"가 보이는 것이 정상입니다.

## 4. Firebase 연동하기

### 4-1. 프로젝트 만들기
1. <https://console.firebase.google.com> 접속 → 교수님 Google 계정으로 로그인.
2. **Firebase 프로젝트 만들기**(또는 **프로젝트 추가**) 클릭 → 프로젝트 이름 입력(예: `nursing-lab`) → **계속**.
3. Gemini / Google 애널리틱스 사용 여부는 **사용 안 함**으로 두어도 됩니다 → **프로젝트 만들기** → **계속**.
   - 요금제는 기본값인 **Spark(무료)** 그대로 둡니다. 결제 정보는 입력하지 않습니다.

### 4-2. 웹 앱 등록 → 설정값 복사
1. 프로젝트 첫 화면 가운데의 **`</>`(웹)** 아이콘 클릭.
2. 앱 닉네임 입력(예: `lab-web`). **"Firebase 호스팅도 설정"은 체크하지 않습니다** → **앱 등록**.
3. 화면에 나오는 `const firebaseConfig = { … }` 안의 값 6개를 메모장에 복사해 둡니다.

   | firebaseConfig 항목 | Netlify 환경변수 이름 |
   |---|---|
   | `apiKey` | `VITE_FIREBASE_API_KEY` |
   | `authDomain` | `VITE_FIREBASE_AUTH_DOMAIN` |
   | `projectId` | `VITE_FIREBASE_PROJECT_ID` |
   | `storageBucket` | `VITE_FIREBASE_STORAGE_BUCKET` |
   | `messagingSenderId` | `VITE_FIREBASE_MESSAGING_SENDER_ID` |
   | `appId` | `VITE_FIREBASE_APP_ID` |

   - 나중에 다시 보려면: 왼쪽 위 톱니바퀴 → **프로젝트 설정** → **일반** 탭 → 아래쪽 **내 앱** → **구성** 선택.
   - 이 값들은 브라우저에 공개되는 값이라 비밀번호가 아닙니다. 데이터 보호는 4-5의 보안 규칙이 담당합니다.
4. **콘솔로 이동** 클릭.

### 4-3. Google 로그인 켜기 + 승인된 도메인 추가
1. 왼쪽 메뉴 **빌드(Build) → Authentication** → **시작하기**.
2. **로그인 방법(Sign-in method)** 탭 → **Google** 클릭 → **사용 설정** 스위치 켜기 →
   **프로젝트 지원 이메일**에서 교수님 이메일 선택 → **저장**.
3. **설정(Settings)** 탭 → 왼쪽 **승인된 도메인(Authorized domains)** → **도메인 추가** →
   Netlify 주소에서 `https://`를 뺀 부분(예: `nursing-lab.netlify.app`) 입력 → **추가**.
   > ⚠️ 이 단계를 빠뜨리면 로그인 버튼을 눌렀을 때 "승인된 도메인에 등록되어 있지 않습니다" 오류가 납니다.
   > Netlify 주소를 바꾸면 새 주소도 다시 추가해야 합니다.

### 4-4. Firestore 데이터베이스 만들기
1. 왼쪽 메뉴 **빌드(Build) → Firestore Database** → **데이터베이스 만들기**.
2. 버전(에디션)을 묻는다면 **Standard**를 선택합니다.
3. 데이터베이스 ID는 `(default)` 그대로, 위치는 **`asia-northeast3 (Seoul)`** 선택 → **다음**.
   > ⚠️ 위치는 나중에 바꿀 수 없습니다.
4. **프로덕션 모드에서 시작** 선택 → **만들기**.

### 4-5. 보안 규칙 게시
1. Firestore Database 화면 위쪽의 **규칙(Rules)** 탭 클릭.
2. 편집창의 기존 내용을 모두 지웁니다(`Ctrl + A` → `Delete`).
3. 이 저장소의 `firestore.rules` 파일을 열어(GitHub에서 파일 클릭 → 오른쪽 위 **복사** 아이콘) 내용 전체를 붙여 넣습니다.
4. **관리자 이메일 확인**: 붙여 넣은 내용의 `isAdmin()` 안 이메일(현재 `sy.shon@kmu.kr`)이 교수님 Google 로그인 이메일과 같은지 확인합니다. 다르면 고칩니다.
   (GitHub의 `firestore.rules` 파일도 같은 이메일로 고쳐 두면 나중에 헷갈리지 않습니다.)
5. **게시(Publish)** 클릭.

> 💡 **`firestore.rules` 파일이 바뀌면(예: 새 게시판 추가) 이 4-5 단계를 다시 해야** 새 기능이 동작합니다.
> 다시 하지 않으면 새 기능에서 "접근 권한이 없습니다"가 나옵니다.

### 4-6. Netlify에 환경변수 입력 → 재배포
1. <https://app.netlify.com> → 내 프로젝트 클릭.
2. **Project configuration**(Site configuration) → 왼쪽 **Environment variables** → **Add a variable** →
   **Add a single variable**.
3. 아래 7개를 하나씩 입력합니다(Key = 이름, Value = 값). 나머지 옵션은 기본값 그대로 → **Create variable**.
   - `VITE_FIREBASE_API_KEY` ~ `VITE_FIREBASE_APP_ID` 6개: 4-2에서 복사한 값 (따옴표 `"` 없이 값만)
   - `VITE_ADMIN_EMAIL`: 교수님 Google 계정 이메일 (4-5에서 규칙에 넣은 이메일과 **똑같이**)
   > 💡 한 번에 넣으려면 **Add a variable → Import from a .env file** 을 누르고 `.env.example` 형식으로
   > `이름=값` 7줄을 붙여 넣어도 됩니다.
4. 왼쪽 메뉴 **Deploys** → 오른쪽 **Trigger deploy** → **Deploy project**(Deploy site) 클릭.
   > 환경변수는 **다시 배포해야** 적용됩니다.
5. 1~2분 뒤 사이트를 새로고침하면 "Firebase 연동 후…" 안내가 사라지고 로그인 버튼이 보입니다.

## 5. 첫 사용 순서

1. **관리자 로그인**: 사이트 → 오른쪽 위 **로그인** → **Google로 로그인** → 교수님 계정 선택.
   헤더에 이름·사진과 "관리자" 표시, 메뉴에 **관리자**가 보이면 성공입니다.
2. **자료 올려 보기**: **관리자** 메뉴 → **+ 새 자료 작성** → 분류·제목·요약·본문·태그 입력 →
   첨부 파일은 Google Drive에 올린 뒤 **공유 → 링크 복사**한 주소를 붙여 넣기 → **저장**.
3. **학생에게 주소 공유**: Netlify 주소(`https://○○○.netlify.app`)를 학생들에게 알립니다.
4. **학생 로그인**: 학생이 Google로 로그인하면 "승인 대기 중입니다" 화면이 보입니다.
5. **승인**: 교수님이 **관리자** → **회원 관리 → 승인 대기**에서 학생 이름 옆 **승인** 클릭.
   잘못 신청한 사람은 **거절**(신청 기록 삭제)을 누릅니다.
6. 학생은 **승인 여부 다시 확인** 버튼(또는 새로고침)을 누르면 자료와 토론을 이용할 수 있습니다.

> 회원 **삭제**를 눌러도 그 사람의 Google 계정이 사라지지는 않습니다. 다시 로그인하면 승인 대기 상태로 새로 등록되므로,
> 다시 승인하지 않으면 자료를 볼 수 없습니다.

## 6. 무료 요금제 한도와 주의사항

**Firebase Spark(무료) 요금제 – Firestore 하루 한도** (2026년 기준, Google 정책에 따라 바뀔 수 있음)

| 항목 | 하루 무료 한도 | 이 사이트에서 쓰이는 경우 |
|---|---|---|
| 문서 읽기 | 50,000회 | 목록·자료·댓글 보기 (목록 1번 열 때 자료 수만큼) |
| 문서 쓰기 | 20,000회 | 자료 작성·수정, 댓글 작성·수정, 회원 승인 |
| 문서 삭제 | 20,000회 | 자료·댓글·회원 삭제 |
| 저장 용량 | 1 GiB | 글자 데이터만 저장하므로 충분함 |

- 연구실 규모(교수 1명 + 대학원생 수십 명)에서는 한도에 거의 닿지 않습니다. 한도를 넘으면 그날은 "무료 사용량 한도를 넘었습니다"
  오류가 나고, 한국 시간 오후 4~5시경(태평양 시간 자정)에 초기화됩니다. **요금이 자동으로 청구되지는 않습니다.**
- **파일은 Google Drive 등의 링크로만 첨부합니다.** 무료 요금제에서는 Firebase에 파일을 저장(Cloud Storage)할 수 없습니다.
  Drive 공유 설정을 **"링크가 있는 모든 사용자"** 대신 **"제한됨 + 학생 이메일 추가"**로 하면 더 안전합니다.
- **환자·연구참여자 등 개인 식별 정보(이름, 등록번호, 연락처, 얼굴 사진, 녹음 등)는 절대 올리지 마세요.**
  댓글에도 마찬가지입니다. IRB 승인 범위와 기관 연구윤리 지침을 따르세요.
- Netlify 무료 요금제도 연구실 규모의 방문량에는 충분합니다.
- `.env` 파일이나 설정값을 GitHub 이슈·메일 등에 붙여 넣지 마세요(공개되어도 보안 규칙이 막아 주지만 습관상 안전하게).

## 7. 수동 테스트 체크리스트

배포 후 아래 항목을 하나씩 확인하세요. 서로 다른 계정으로 시험할 때는 브라우저의 **시크릿(InPrivate) 창**을 쓰면 편합니다.

### Firebase 연동 전 (환경변수 없음)
- [ ] 홈(`/`)에 연구실 이름·연구 분야·교수 소개·연락처가 보인다.
- [ ] `/research`, `/courses`, `/questions`, `/login`, `/pending`, `/admin`, `/posts/아무거나` 에서 "Firebase 연동 후 사용할 수 있습니다"가 보인다.
- [ ] 헤더에 로그인 버튼이 없고, 오류 화면이 나오지 않는다.
- [ ] 아무 주소(예: `/abc`)에서 404 페이지가 보이고, 주소창에서 새로고침해도 Netlify 404가 아닌 사이트 화면이 나온다.

### 방문자 (로그인 안 함)
- [ ] 홈이 정상적으로 보인다.
- [ ] **연구 자료** / **수업 자료** 메뉴를 누르면 로그인 화면으로 이동한다.
- [ ] `/admin` 주소로 직접 들어가면 로그인 화면으로 이동한다.
- [ ] 헤더 메뉴에 **관리자**가 없다.

### 승인 대기 (처음 로그인한 학생)
- [ ] Google 로그인 후 "승인 대기 중입니다" 화면으로 이동한다.
- [ ] 헤더에 이름·사진·"승인 대기" 표시와 로그아웃 버튼이 있다.
- [ ] `/research`, `/courses`, `/questions`, `/posts/…`, `/admin`에 들어가면 승인 대기 화면으로 돌아온다.
- [ ] 관리자 화면의 **승인 대기** 목록에 이 학생이 나타난다.

### 회원 (승인된 학생)
- [ ] **승인 여부 다시 확인**을 누르면 연구 자료 목록으로 이동한다.
- [ ] 연구 자료 / 수업 자료가 분류별로 카드(제목·요약·태그·작성일)로 보인다.
- [ ] 자료를 누르면 본문(줄바꿈 유지)과 첨부 링크가 보이고, 링크는 새 창으로 열린다.
- [ ] 댓글을 쓸 수 있고, 글자 수(최대 3000자)가 표시된다.
- [ ] 본인 댓글만 **수정**·**삭제** 버튼이 보이고, 실제로 수정·삭제된다.
- [ ] 다른 사람 댓글에는 수정·삭제 버튼이 없다.
- [ ] `/admin`에 들어가면 홈으로 이동한다.
- [ ] 댓글에 `<b>굵게</b>` 같은 HTML을 써도 글자 그대로 보인다.
- [ ] **질문 게시판**에서 **+ 질문하기**로 질문을 올릴 수 있고, 폼 위에 개인정보 경고가 보인다.
- [ ] 본인 질문에는 **해결됨으로 표시**·**수정**·**삭제** 버튼이 있고, 다른 사람 질문에는 없다.
- [ ] 다른 사람 질문에 답변을 달 수 있고, 본인 답변만 수정할 수 있다.
- [ ] 본인 질문을 삭제하면 달린 답변도 함께 사라진다.
- [ ] 목록의 **전체 / 답변 대기 / 해결됨** 버튼으로 질문을 거를 수 있다.

### 관리자 (교수)
- [ ] 로그인하면 헤더에 "관리자" 표시와 **관리자** 메뉴가 보인다(회원 문서가 없어도).
- [ ] 회원 관리에서 승인 대기 학생을 **승인**하면 회원 목록으로 옮겨진다.
- [ ] **거절**/**삭제**를 누르면 확인 창이 뜨고, 목록에서 사라진다.
- [ ] 자료 작성 폼 맨 위에 "환자·연구참여자 등 개인 식별 정보를 올리지 마세요." 경고가 보인다.
- [ ] 자료를 작성(링크 여러 개 포함)·수정·삭제할 수 있고, 목록에 바로 반영된다.
- [ ] `https://`로 시작하지 않는 링크를 넣으면 저장되지 않고 안내 문구가 나온다.
- [ ] 다른 사람 댓글에도 **삭제** 버튼이 보이고 삭제된다(수정 버튼은 본인 댓글에만).
- [ ] 질문 게시판에서 학생 질문을 **해결됨으로 표시**하거나 **삭제**할 수 있다(수정은 불가).

## 8. 폴더 구조

```
├─ public/_redirects            # 새로고침해도 404가 나지 않게 하는 Netlify 설정
├─ src/
│  ├─ main.jsx, App.jsx         # 시작점, 주소별 화면 연결(라우팅)
│  ├─ config/site.js            # ★ 연구실 소개 문구 (교수님이 직접 수정)
│  ├─ lib/                      # firebase.js(초기화), format.js(날짜·링크 도우미), useLoader.js(불러오기 도우미)
│  ├─ contexts/AuthContext.jsx  # 로그인 상태와 역할
│  ├─ services/                 # Firestore 읽기·쓰기 (posts, comments, questions, users, errors)
│  ├─ components/               # 화면 부품 (헤더, 푸터, 카드, 댓글, 관리자 폼 등)
│  ├─ pages/                    # 화면 (홈, 자료 목록·상세, 질문 목록·상세, 로그인, 승인 대기, 관리자, 404)
│  └─ styles/global.css         # 디자인
├─ firestore.rules              # ★ 보안 규칙 (Firebase 콘솔에 붙여 넣기)
├─ netlify.toml                 # Netlify 빌드 설정
└─ .env.example                 # 환경변수 견본
```

### 보안에 대해
- 화면에서 관리자 메뉴를 보여 주는 판단(`VITE_ADMIN_EMAIL`)은 **편의 기능**입니다.
  실제로 누가 무엇을 읽고 쓸 수 있는지는 **`firestore.rules`가 서버에서 검사**하므로, 화면을 조작해도 데이터에 접근할 수 없습니다.
- 사용자가 입력한 글(댓글·본문)은 모두 글자 그대로만 표시되며, HTML로 해석되지 않습니다.
